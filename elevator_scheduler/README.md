# 电梯调度系统 (Elevator Scheduling System)

这是一个用Go语言实现的电梯调度系统，展示了如何使用Go的并发特性来解决实际的调度问题。

## 🏢 系统概述

当小明要回家上楼时，他会按下两个客梯的按钮。同时，其他楼层的人也可能在使用电梯。这个系统模拟了真实的电梯调度场景，展示了电梯是如何智能地响应和处理多个请求的。

## 🔧 核心特性

### 1. 并发架构
- **多电梯并发运行**：每部电梯在独立的goroutine中运行
- **线程安全**：使用mutex保护共享状态
- **通道通信**：使用channel进行goroutine间通信

### 2. 智能调度算法
- **SCAN算法**：电梯继续当前方向运行，直到该方向没有更多请求
- **最小成本分配**：根据距离、方向一致性和队列长度选择最优电梯
- **动态方向调整**：当当前方向没有请求时自动改变方向

### 3. 成本计算策略
```go
cost = 距离成本 + 方向不一致惩罚 + 队列长度成本
```

## 📋 系统组件

### 核心结构体

#### `Elevator` - 电梯
```go
type Elevator struct {
    ID            int         // 电梯ID
    CurrentFloor  int         // 当前楼层
    Direction     Direction   // 当前方向
    Requests      []Request   // 请求队列
    IsMoving      bool        // 是否在移动
    mutex         sync.Mutex  // 保护电梯状态的互斥锁
    requestChan   chan Request // 接收请求的通道
    stopChan      chan bool   // 停止信号
}
```

#### `ElevatorScheduler` - 调度器
```go
type ElevatorScheduler struct {
    Elevators   []*Elevator
    RequestChan chan Request
    mutex       sync.Mutex
}
```

#### `Request` - 电梯请求
```go
type Request struct {
    Floor     int       // 请求楼层
    Direction Direction // 请求方向
    Timestamp time.Time // 请求时间
}
```

## 📊 调度策略详解

### 1. 请求分发策略
当有新的电梯请求时，调度器会：
1. 计算每部电梯服务该请求的成本
2. 选择成本最低的电梯
3. 将请求分配给该电梯

### 2. SCAN算法实现
每部电梯使用SCAN算法（也称为电梯算法）：
1. **继续当前方向**：优先服务当前方向上的请求
2. **到达边界后转向**：当当前方向没有更多请求时改变方向
3. **最近优先**：在同一方向上优先服务最近的楼层

### 3. 成本计算公式
```
基础成本 = |当前楼层 - 请求楼层| × 10
方向惩罚 = 方向不一致 ? 50 : 0
队列成本 = 请求队列长度 × 5
总成本 = 基础成本 + 方向惩罚 + 队列成本
```

## 🎯 模拟场景

系统模拟了以下场景：
1. **小明在1楼按两个电梯按钮**（模拟现实中按多个电梯的情况）
2. **其他楼层的随机请求**：
   - 5楼有人要下楼
   - 8楼有人要上楼
   - 3楼有人要下楼
   - 10楼有人要下楼
   - 6楼有人要上楼

## 🔍 并发编程要点

### 1. Goroutine使用
- 每部电梯运行在独立的goroutine中
- 调度器的请求分发器运行在单独的goroutine中
- 模拟用户请求的函数也使用goroutine

### 2. 同步机制
- **Mutex**：保护电梯状态和调度器状态
- **Channel**：用于goroutine间的通信
- **Select语句**：处理多个channel的非阻塞操作

### 3. 资源管理
- 优雅关闭：通过stopChan通知电梯停止
- 内存管理：及时清理已完成的请求
- 超时处理：避免无限等待

## 🔧 扩展功能

1. **更复杂的调度算法**：如LOOK算法、C-SCAN算法
