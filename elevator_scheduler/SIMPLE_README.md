# 简化电梯调度系统 (Simple Elevator Scheduling System)

这是一个简化的电梯调度系统，**只有1部电梯**，重点展示**SCAN调度算法**的工作原理。

## 🎯 问题背景

小明要回家上楼时，会按电梯按钮。同时其他楼层的人也可能在使用电梯。这个简化系统专注于展示：**电梯是如何通过SCAN算法来决定下一步去哪个楼层的？**

## 🔧 核心特性

### 1. 简化架构
- **1部电梯**，10层楼
- **详细的调度决策过程**输出
- **SCAN算法**的完整实现

### 2. SCAN算法详解
SCAN算法（也称为电梯算法）的核心思想：
```
1. 电梯继续当前方向运行
2. 服务路径上的所有请求
3. 到达边界后改变方向
4. 重复上述过程
```

系统会详细输出每次调度的决策过程：

## 📋 算法流程

### 1. 电梯空闲时
- 选择**距离最近**的请求
- 设置电梯运行方向

### 2. 电梯运行时（SCAN算法）
- **继续当前方向**：优先服务同方向的请求
- **选择最近楼层**：在同方向中选择最近的楼层
- **方向转换**：当前方向没有请求时改变方向

### 3. 方向转换策略
- **上行→下行**：选择最高的下行楼层
- **下行→上行**：选择最低的上行楼层

### 复杂调度场景
```
当前位置: 8楼, 方向: 上行
请求队列: 3楼下行, 10楼下行, 6楼上行

SCAN算法分析:
- 10楼 (同方向) ← 优先选择
- 3楼, 6楼 (反方向)

决策: 先去10楼，然后改变方向处理其他请求
```

## 🔍 关键代码

### SCAN算法核心逻辑
```go
if e.Direction == Up {
    // 收集同方向（上行）的请求
    for _, req := range e.Requests {
        if req.Floor >= e.CurrentFloor {
            sameDirection = append(sameDirection, req.Floor)
        } else {
            oppositeDirection = append(oppositeDirection, req.Floor)
        }
    }
    
    if len(sameDirection) == 0 {
        // 没有上行请求，改变方向为下行
        e.Direction = Down
        return selectHighestFloor(oppositeDirection)
    } else {
        // 选择最近的上行楼层
        return selectNearestFloor(sameDirection)
    }
}
```

## 🎓 学习价值

这个简化系统帮助理解：

1. **SCAN算法原理**：为什么电梯不会频繁改变方向
2. **调度决策过程**：电梯如何选择下一个目标楼层
3. **效率优化**：如何减少电梯的总运行距离
4. **并发编程**：Go语言的goroutine和channel使用
