# 读者-写者问题

## 背景
小明最近在学习 mysql 的 myisam 引擎。myisam 读取性能高，写入性能低。
读取性能高的原因是：
不会阻塞其他用户对同一表请求，但会阻塞对同一表的写请求
写入性能低的原因是：
写入时需要加表级锁，阻塞其他用户对同一表的读和写操作

## 要求
请你实现写优先的读写操作，即当有写者在写时|在等待时，读者必须等待；当没有写者在写或等待时，读者可以读取数据。
请你模拟 myisam 引擎的读写操作，实现对 content 的读写操作。每次读取数据之后，返回 content 和 读取数据花费的时间。

## 思路

先捋清楚需要哪些信息：
读：
1、等待写的写者数量
2、当前是否有写者正在写

写：
1、是否有读者正在读
2、等待写的写者数量

先看读怎么实现：
如果发现有写者在写或者有写者在等待，则等待。cond.wait()
如果正在读的读者数量为0，则通知等待写的写者可以写。cond.broadcast()

写怎么实现：
如果发现有写者正在写，或者有读者正在读，则等待。cond.wait()
写者读完数据后，为了满足写优先，需要优先唤醒写者，再唤醒读者。cond.broadcast()

所以这里的 cond，需要两个，一个用于读，一个用于写。readerCond 和 writerCond
